## 0. 저장소 조사 결과 — 무엇이 있고 무엇이 없나

**이미 구현된 것을 다시 만들지 않는다**: 조건 구조화(D-01~D-05)·D-15·리디자인은 그대로 둔다.

## 1. P0 요구사항 (계획서 §3 P0 행 그대로)

목록·상세 / 이름·주소 검색·구 선택 / 사용자가 선택한 위치 기준 가까운 순 /
목록에서 전화·외부 지도·주소 복사 / 안내된 진료시간·야간 응급 조건 /
영어 응대 4상태 / 항목별 출처·확인일·재확인 / 고정 한국어 문의 문구(영어 뜻·복사·확대) /
관리자 등록·수정·임시저장·공개·숨김·확인 기록.

**P0에서 하지 않는 것**: 진료 준비 카드, AI 번역, 즐겨찾기·오류 제보, 예약·결제, 병원 직접 응답,
`지금 접수 가능` 계산, 지도 임베드, Places API.

## 2. 확정 결정 (D-16 ~ D-20)

기존 문서의 `D-01`~`D-15`가 사용 중이라 **D-16**부터 부여한다.

### D-16. 병원은 `Place`와 분리된 `VetClinic` 도메인이다

`Category.VET`을 추가하지 않는다. 근거는 세 가지다.
(a) `Place.location`이 non-null이라 좌표 미확보 병원을 담을 수 없다.
(b) `Verification.placeId`가 필수 FK라 항목별 확인 기록을 붙일 수 없다.
(c) VET이 `Category`에 들어오면 홈 카테고리 탭·`filterPlaces`·`resolveDogAccess`·반려견 입장
판정에 그대로 흘러든다. 병원은 동반 조건 판정 대상이 아니다.

브랜드 UI·인증·관리자 가드·위치·거리·지도 링크·i18n·운영시간 스키마는 **재사용**한다.

### D-17. 확인 근거는 **항목별**이고 **값에 묶인다**

`VetVerification`은 `target`(BASIC / HOURS / ENGLISH_SUPPORT / AFTER_HOURS)별로 쌓이고,
확인한 **값의 스냅샷(`verifiedValue`)** 을 함께 저장한다.

- 주소를 고쳐도 영어 응대 확인일은 갱신되지 않는다(항목이 다르므로).
- **값이 바뀌면 그 항목의 이전 확인 기록은 더 이상 유효하지 않다.** 현재 값과
  `verifiedValue`가 다르면 화면은 `미확인`으로 읽는다 — 옛 값의 확인 기록이 새 값을
  검증한 것처럼 보이지 않게 하는 장치다.
- 판정은 `resolveVetItem()` 한 곳에서만 한다. 화면마다 복제하지 않는다.

### D-18. 병원 재확인 경계는 **30일**이며 일반 장소의 90일과 분리한다

`VET_RECHECK_AFTER_DAYS = 30`. 일반 장소의 `RECHECK_AFTER_DAYS = 90`은 그대로 둔다.
확인 시각으로부터 30일 **이상**이면 재확인 필요다(경계 포함, 장소 규칙과 같은 방식).

**재확인이 필요해도 병원을 숨기지 않는다.** 기본 목록에 남기고 상태와 확인 이력을 보여준다.

### D-19. `안내 확인` 필터는 **유효한 근거가 있는 가능·조건부**만 포함한다

`영어 응대 안내 확인` / `야간 진료 안내 확인` 필터는 해당 항목이
`AVAILABLE` 또는 `CONDITIONAL`이면서 **값이 일치하고 30일이 지나지 않은** 확인 기록을 가진
병원만 통과시킨다. `UNAVAILABLE`·`UNKNOWN`·재확인 기한 경과는 제외한다.
조건부는 제외하지 않고 **조건 문구를 함께** 보여준다.

D-03·D-12(긍정 조건 필터는 확인된 일치 값만)와 같은 규칙을 병원 항목에 적용한 것이다.

### D-20. 공개 기준은 **기본 정보에만** 걸린다

`VISIBLE`로 두려면 병원명·주소·전화가 있고 **BASIC 항목의 유효한 확인 근거**가 있어야 한다.
영어 응대·야간 진료가 `UNKNOWN`이어도 공개를 막지 않는다 — 확인된 범위를 보여주는 것이
계획서 §5의 방침이다. 검증은 `canPublishClinic()` 한 곳에 두고 폼과 서버가 함께 쓴다.

### 표시 규칙 (결정 아님 · 계획서를 코드 규칙으로 옮긴 것)

- 시간 미등록 → **휴무 아님**. `안내된 진료시간 없음`.
- 영어 응대 미확인 → **불가 아님**. `미확인`.
- 병원명의 `24시`·영어 홈페이지 존재만으로 야간 진료·영어 응대를 추정하지 않는다.
- `지금 접수 가능`을 계산하지 않는다. 시간표와 운영 조건만 보여주고 `방문 전 전화 확인`을 붙인다.
- 좌표가 없으면 **거리를 만들지 않는다.** 거리순에서 좌표 있는 병원 뒤로 보낸다.
- 위치가 없을 때 기본 정렬은 **최근 확인순**이며 그 기준 항목을 화면에 명시한다. `내 주변`이라 부르지 않는다.

## 3. 데이터 설계

```prisma
enum VetServiceStatus     { AVAILABLE CONDITIONAL UNAVAILABLE UNKNOWN }
enum VetVerificationTarget { BASIC HOURS ENGLISH_SUPPORT AFTER_HOURS }

model VetClinic {
  id, nameKr, nameEn?, district, address, phone,
  location geography(Point,4326)?   // nullable — Place와 다른 점
  website?, hours Json?, hoursNote?,
  englishSupport VetServiceStatus, englishSupportCondition?,
  afterHours     VetServiceStatus, afterHoursCondition?,
  visibility PlaceVisibility,       // 재사용
  adminNote?,                       // 내부 메모. 사용자 화면에 내보내지 않는다
  collectedAt?,                     // 데이터 수집일 — 확인일과 다르다
  createdAt, updatedAt              // updatedAt = 정보 수정일
  verifications VetVerification[]
}

model VetVerification {
  id, clinicId, target, method(VerificationMethod 재사용),
  verifiedBy, verifiedAt, sourceUrl?, note?,
  verifiedValue?   // D-17: 이 기록이 확인한 값의 스냅샷
}
```

**세 날짜를 구분한다**: `collectedAt`(수집) · `updatedAt`(수정) · `verification.verifiedAt`(확인).

## 4. 화면

| 경로 | 내용 |
|---|---|
| `/[locale]/vets` | 검색·구 선택·필터 2개·내 위치 버튼 → 카드 목록 |
| `/[locale]/vets/[id]` | 병원명·전화/지도 → 시간표 → 야간·영어 조건 → 주소 → 항목별 확인 근거 → 한국어 문의 문구 |
| `/[locale]/admin/vets` `[/new]` `[/[id]/edit]` | 목록·등록·수정 (기존 `/admin/*` 가드가 보호) |

- 카드 순서: **병원명 → 구·주소·거리 → 안내된 시간 → 응대 조건 → 확인일 → 전화·지도**.
- 사진 없음. 히어로 일러스트·빈 사진 영역을 두지 않는다.
- 모바일 상세는 하단 고정 전화·지도 바. `env(safe-area-inset-bottom)`과 본문 하단 여백으로
  본문·키보드 포커스를 가리지 않게 한다.
- 언어 전환 시 `q`·`district`·필터·`sort`는 URL 쿼리에 있으므로 자동 보존된다.
- 빈 상태 3종을 구분한다: **필터 결과 0건**(조건 해제 제공) / **등록 병원 없음** / **조회 실패**(재시도).

## 5. 구현 순서

1. Prisma 스키마 + 마이그레이션 SQL (적용하지 않음)
2. `src/lib/vets/*` — 상수·확인 판정·재확인·검증·필터·조회·저장·문의 문구
3. `messages/{ko,en}.json`
4. 공개 화면(목록·상세) + 컴포넌트
5. 관리자 화면(목록·등록·수정) + 서버 액션
6. `Header` 링크 교체
7. 테스트 + 브라우저 검증(격리 fixture)

## 6. 완료 기준

| 구분 | 기준 |
|---|---|
| **P0 코드 구현 완료** | 위 화면·저장·판정·필터가 동작하고 회귀 테스트가 통과 |
| **실제 병원 데이터 확보** | 별개. 공개 정보로 표본만 정리하고 운영 공개는 하지 않는다 |
| **공개 준비 완료** | 별개. 마이그레이션 적용 + 실데이터 검수 + 운영 판단이 남는다 |

**DB 실검증의 한계**: `.env.local`에는 Supabase 운영 DB 하나뿐이고 개발·테스트 DB가 없다.
마이그레이션은 작성·검토하되 **적용하지 않는다.** 따라서 런타임 DB 조회는 검증 범위 밖이며,
화면 검증은 격리 fixture로 수행한다.
