# GPT-6 Astra API — 연동 검토와 유의사항

TourAPI가 내려주는 **자유 텍스트 동반 조건**을 `policyDetails` 구조로 옮기는 일에
LLM을 쓸지 검토한 문서다. 모델 스펙은 2026-09-15에 공식 문서로 확인했고,
이 저장소에는 아직 LLM 의존성이 **없다**(`package.json`에 `openai`·`@ai-sdk`·`anthropic` 모두 없음).

## 1. 확인된 모델 스펙

2026-09-03 출시. 지식 컷오프가 **2026-04-30**이라, 그 이후의 TourAPI 명세 변경이나
법령 변화는 모델이 모른다. 우리가 프롬프트로 넣어줘야 한다.

| 항목 | 값 |
|---|---|
| 모델 ID | `gpt-6-astra` (스냅샷 1종) |
| 컨텍스트 | 1,050,000 토큰 (입력 최대 922K) |
| 최대 출력 | 128,000 토큰 |
| 입력 / 출력 | $10 / $50 (100만 토큰당) |
| 캐시된 입력 / 캐시 쓰기 | $1 / $12.50 |
| 입력 모달리티 | 텍스트, 이미지 (출력은 텍스트만) |
| 엔드포인트 | `v1/responses`, `v1/chat/completions`, `v1/batch` |
| 추론 강도 | `low` / `medium` / `high` / `xhigh` / `max` |
| 지원 기능 | 스트리밍, **Structured Outputs**, function calling, 프롬프트 캐싱 |
| Rate limit | Tier 1: 500 RPM / 500K TPM — Tier 5: 15,000 RPM / 40M TPM |

과금 임계값이 두 개 있다.

- **입력 272K 토큰 초과** 요청은 입력·캐시 2배, 출력 1.5배로 과금된다.
- Batch·Flex는 50% 할인, Fast 모드는 2배.

우리 작업은 장소 1건당 입력이 수천 토큰이라 272K에 걸릴 일이 없다. 대신
**한 번에 여러 장소를 몰아넣는 방식으로 짜면 걸릴 수 있으니** 배치 크기를 키울 때 확인한다.

## 2. 이 서비스에서 LLM이 필요한 지점은 한 곳뿐이다

`docs/03-analysis` 기준으로 지금 구조에서 기계가 못 푸는 건 TourAPI `detailPetTour2`의
`etcAcmpyInfo` 한 필드다. 실측 샘플(`data/tour-api/place-129438-*.json`, 장태산자연휴양림):

```
"etcAcmpyInfo": "- 맹견의 경우, 입마개 착용 필수- 숙박시설, 출렁다리, 스카이 타워는 동반 불가- 배변 봉투 지참 및 배변 처리 필수"
```

이 한 줄이 우리 스키마에서는 셋으로 갈라진다.

| 원문 조각 | 대상 |
|---|---|
| 맹견의 경우, 입마개 착용 필수 | `PlaceCondition.muzzle = CONDITIONAL` |
| 숙박시설 / 출렁다리 / 스카이 타워는 동반 불가 | `policyDetails.spaceExceptions` 3건 |
| 배변 봉투 지참 및 배변 처리 필수 | `policyDetails.hygiene` |

구분자 `- `가 줄바꿈 없이 붙어 있어 정규식 분리가 불안정하고, 표현도 장소마다 제각각이다.
**여기가 LLM을 쓸 이유가 있는 유일한 지점이다.**

반대로 아래는 LLM을 쓰면 안 된다 — 규칙으로 정확히 되는 일이다.

- `mapx`/`mapy` → 좌표 (단순 매핑)
- `acmpyTypeCd: "일부구역 동반가능"` → `IndoorPolicy.PARTIAL_AREA` (값 목록 고정 시 사전 매핑)
- `usetime` → `Place.hours` (스키마가 자유 텍스트 저장을 금지한다. LLM으로 추측해 채우면 원칙 위반)

## 3. 가장 중요한 유의사항 — LLM 출력은 "확인"이 아니다

이 서비스의 근간은 **확인된 것만 말한다**이다. `UNKNOWN`은 "없음"이 아니라 "확인되지 않음"이고,
`Verification`은 사람이 전화·방문·공지로 확인한 기록이다.

LLM이 원문에서 뽑아낸 값은 **원문의 재구성일 뿐 확인이 아니다.** 원문 자체가 틀렸거나
오래됐을 수 있고, 모델이 없는 조건을 만들어낼 수도 있다.

| 해도 되는 것 | 하면 안 되는 것 |
|---|---|
| 원문 → `policyDetails` 초안 생성 | 초안을 그대로 `visibility = VISIBLE`로 공개 |
| 사람 검토 화면에 **원문과 나란히** 제안 표시 | `Verification` 레코드를 LLM 이름으로 생성 |
| 원문에 없는 항목을 `UNKNOWN`으로 두기 | 빈 값을 "제한 없음"으로 추론해 채우기 |
| 불확실한 건 `uncertainties`에 질문으로 남기기 | `VerificationMethod`에 LLM용 값 추가 |

`export-tour-sample.cjs`가 스냅샷에 `reviewStatus: 'UNREVIEWED'`를 박아둔 것이 이 전제다.
LLM을 붙여도 **`UNREVIEWED` → 사람 검토 → `DRAFT` → 공개** 경로는 그대로 유지한다.
LLM은 이 경로의 입력 품질을 올릴 뿐, 단계를 건너뛰는 도구가 아니다.

## 4. 구조상 어디에 붙이나

### 4.1 스키마를 두 번 쓰지 않는다

`src/lib/places/policy-details.ts`의 `policyDetailsSchema`가 이미 zod `strictObject`이고,
이 저장소는 **zod v4**(`^4.4.3`)를 쓴다. v4에는 `z.toJSONSchema()`가 내장돼 있으므로
Structured Outputs의 JSON Schema를 **손으로 다시 적지 말고 여기서 파생시킨다.**

프롬프트용 스키마와 저장용 스키마가 갈라지는 순간 둘이 어긋나고, 그 어긋남은
런타임에야 드러난다. 파생시키면 `policyDetailsSchema`를 고칠 때 프롬프트도 같이 따라온다.

### 4.2 제안 배치

```
src/lib/places/
  policy-details.ts          (기존 — 단일 스키마 출처, 수정 없음)
  policy-extract.ts          (신규 — 원문 → PolicyDetails 초안. LLM 호출 경계)
  policy-extract.test.ts     (신규 — 고정 샘플로 파싱·검증 계약 테스트)
```

경계 규칙 세 가지.

1. **`policy-extract.ts` 바깥은 LLM을 모른다.** 반환 타입은 `PolicyDetails`(+ 신뢰도·원문 인용)
   이고, 호출부는 이게 어디서 왔는지 몰라도 된다. 나중에 모델을 바꾸거나 규칙 기반으로
   되돌릴 때 이 파일만 건드린다.
2. **응답은 반드시 `policyDetailsSchema.parse()`를 통과시킨다.** Structured Outputs가
   형식을 보장해도 **내용이 맞다는 뜻은 아니다.** 스키마 통과는 최소 조건이지 검증이 아니다.
3. **서버 전용.** 키가 클라이언트 번들에 들어가면 안 된다. `NEXT_PUBLIC_` 접두사를 절대 쓰지 않는다.

### 4.3 추론 강도는 낮게 시작한다

짧은 한국어 문장에서 항목을 뽑는 일이다. `max`로 시작하면 비용과 지연만 커진다.
`low`로 시작해 고정 샘플에서 실패하는 항목이 나올 때만 올린다.

## 5. 비용 — 이 작업 규모에서는 병목이 아니다

장소 1건당 입력 3,000 토큰(스키마 + 지침 + 원문), 출력 400 토큰으로 **가정**한 추정이다.
실제 토큰은 스키마 크기에 좌우되므로 붙인 뒤 실측해야 한다.

| 조건 | 1,000건 기준 |
|---|---|
| 기본 | 입력 3M × $10 + 출력 0.4M × $50 = **약 $50** |
| Batch (50% 할인) | **약 $25** |
| 프롬프트 캐싱 적용 시 | 스키마·지침이 캐시되면 입력분이 $10 → $1 구간으로 내려간다 |

스키마와 지침은 요청마다 동일하므로 **캐싱이 가장 크게 먹히는 형태**다.
급하지 않은 일괄 변환이므로 **Batch + 캐싱**이 기본값이고, Fast(2배)를 쓸 이유가 없다.

다만 **더 싼 모델로 충분한 작업일 가능성이 높다.** 짧은 텍스트에서 항목을 뽑는 건
`gpt-6-astra`가 겨냥한 "가장 어려운 end-to-end 작업"이 아니다.
현행 모델 라인업은 이 문서 작성 시점에 확인하지 않았다 — **고정 샘플로 저가 모델을
먼저 돌려보고, 실패할 때만 Astra로 올리는 순서**를 권한다.

## 6. 운영 유의사항

**키 관리.** `.env.local`에만 두고 `.env.example`에는 빈 문자열을 유지한다.
`.env.example`은 git 추적 파일이다 — 실제 `TOUR_API_SERVICE_KEY` 값이 여기 들어갔던
전례가 있으므로 커밋 전 `git diff .env.example`을 반드시 확인한다.

**Rate limit.** Tier 1은 500 RPM / 500K TPM이다. 1,000건을 병렬로 쏘면 걸린다.
Batch 엔드포인트를 쓰면 애초에 해당 사항이 아니다.

**프롬프트 인젝션.** TourAPI 응답은 공공데이터라 위험이 낮지만, **원문은 데이터이지
지시가 아니다.** 원문을 지침과 같은 층위에 넣지 말고 구분된 필드로 전달한다.
나중에 사용자 제보(`USER_REPORT`) 텍스트에 같은 파이프라인을 쓰면 이 위험이 실제가 된다.

**컷오프.** 모델은 2026-04-30까지만 안다. TourAPI 필드 의미, 우리 enum 정의,
`policyDetails` 규칙은 전부 프롬프트로 제공해야 하며 모델의 사전 지식에 기대면 안 된다.

**안전 동작 변화.** 이전 세대보다 거부가 엄격해졌다고 공지돼 있다.
"맹견", "입마개" 같은 단어가 들어간 원문에서 예상 밖 거부가 나올 수 있으니
거부 응답을 실패로 처리하고 사람 검토 큐로 넘기는 경로를 만들어 둔다.

## 7. 결정이 필요한 것

1. **LLM을 쓸 것인가.** 장소 수십 건 규모면 사람이 직접 읽는 게 빠르고 정확하다.
   수백~수천 건으로 갈 때 의미가 생긴다. → 목표 장소 수가 먼저다.
2. **출처 기록 방식.** `VerificationMethod`에 공공데이터 출처를 담을 값이 없다
   (`PHONE`/`DM`/`WEBSITE`/`ON_SITE`/`USER_REPORT`). enum 추가는 마이그레이션이라 승인이 필요하다.
3. **초안 저장 위치.** LLM 초안을 DB에 둘지(신규 컬럼/테이블 = 마이그레이션),
   `data/tour-api` 옆 파일로 둘지.
4. **모델 선택.** 저가 모델 선행 검증 후 결정.

## 8. 확인되지 않은 것

- API 조직 인증(ID verification) 요구 여부 — 시스템 카드에 언급이 없다. 실제 호출로 확인해야 한다.
- 한국어 추출 품질 — 고정 샘플 없이는 알 수 없다. `place-129438` 1건만으로는 부족하다.
- `acmpyTypeCd` 등 TourAPI 코드성 필드의 값 목록이 문서로 고정돼 있는지 — v4.1 매뉴얼 확인 필요.
