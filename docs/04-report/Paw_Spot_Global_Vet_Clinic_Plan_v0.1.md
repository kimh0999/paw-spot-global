# Paw Spot Global 동물병원 기능 계획안 v0.1

작성일: 2026-09-10  
상태: 제품 방향 제안. 실제 저장소의 최신 코드·스키마를 확인한 뒤 구현 명세로 확정한다.

## 1. 제품 방향

**외국인 보호자가 연락할 동물병원을 찾고, 반려견의 상황을 정확하게 전달하도록 돕는다.**

사용자 경험을 병원 찾기, 연락, 방문 준비까지 연결한다. 첫 화면의 목적은 연락할 병원을 고르는 것이고, 외국어 소통 지원이 Paw Spot Global의 차별점이다.

핵심 사용자 상황은 두 가지다.

- 급하게 문의해야 하는 보호자: 가까운 병원, 안내된 진료시간, 야간·응급 진료 안내, 전화번호가 필요하다.
- 평소 이용할 병원을 찾는 보호자: 영어 응대 조건과 병원 정보를 확인하고, 반려견 정보를 정리해 방문을 준비하고 싶다.

반려견 대상, 대전 우선, ko/en으로 시작한다. 지역 밖에서는 서비스 범위를 알리고 외부 지도 검색으로 연결한다. 전국 서비스나 실제 진료 접수 보장을 표방하지 않는다.

현재 대화에서 확인된 조건 구조화 완료와 리디자인은 유지한다. 기존 긴급 페이지 구상은 참고 이력으로 두되, 이번 방향을 제한하지 않는다. 첨부 자료는 기획서 v2·개발명세서 v1이므로 최신 저장소의 확정 문서와 같다고 가정하지 않는다.

## 2. 차별화할 세 가지 경험

### A. 외국어 응대 조건이 보이는 병원 탐색

영어 응대에 대해 가능·조건부 가능·불가·미확인을 구분하고, 출처와 확인일을 함께 보여준다.

예를 들어 특정 요일에만 영어 상담이 가능하거나 통역 앱을 사용하는 경우라면 그 조건을 노출한다. 영어 홈페이지가 있다는 사실로 실제 영어 진료가 가능하다고 추정하지 않는다.

병원 전체에 포괄적인 ‘검증 완료’를 붙이기보다, 전화번호·진료시간·영어 응대·야간 진료 중 무엇을 확인했는지 알 수 있게 한다.

### B. 바로 사용할 수 있는 문의 문구

첫 출시에는 검수한 고정 문장을 제공한다.

- 지금 반려견을 데리고 방문해도 될까요?
- 오늘 야간 진료가 가능한가요?
- 영어로 상담할 수 있는 직원이나 수의사가 있나요?
- 방문 전에 예약이 필요한가요?

영어 UI에서는 문장의 영어 뜻과 실제 전달할 한국어를 함께 보여준다. 한국어 표시를 크게 확대하거나 복사할 수 있게 한다. 전화 기능은 문구 작성이나 로그인 없이 바로 사용할 수 있어야 한다.

번역 문구는 전화 중 보여주기, 사용자가 선택한 메시지 앱에 붙여넣기 등을 돕는다. 제공되지 않은 병원 메시지 채널을 임의로 만들거나 자동 발송하지 않는다.

### C. 보호자가 확인한 ‘진료 준비 카드’

병원에 같은 설명을 반복하는 부담을 줄이는 확장 기능이다.

카드 항목은 반려견 이름·견종·보호자가 입력한 체중, 관찰한 변화, 시작 시점, 복용약·알레르기(아는 경우), 요청 사항이다. 모르는 값은 비워두거나 ‘모름’으로 남긴다.

기존 반려견 프로필에서는 실제로 저장된 값만 가져오며, 크기 분류를 체중으로 추정하지 않는다. 초기에는 간단한 입력과 고정 표현을 사용하고, AI 자유입력 번역은 후속 단계로 검증한다.

## 4. 화면 구성과 상태

### 목록: /[locale]/vets (제안)

기존 ‘동물병원 준비 중’ 메뉴를 실제 목록 진입점으로 바꾼다. 이미 관련 라우트가 있다면 중복 화면을 만들지 않도록 구현 전에 확인한다.

상단에는 짧은 안내, 이름·주소 검색, 구 선택, 내 위치 사용 버튼을 둔다. 초기 필터는 ‘야간 진료 안내 확인’, ‘영어 응대 안내 확인’ 정도로 제한한다.

카드는 병원명, 주소·직선거리, 안내된 시간, 확인된 응대 조건, 확인일, 전화·지도 버튼 순서로 구성한다. 병원 사진은 필수 정보가 아니므로 사진이 없어도 완성된 카드가 되게 한다.

현재 브랜드 색·한글 서체·버튼 체계를 재사용하되, 병원 목록은 전화와 시간 정보의 우선순위를 높인다. 넓은 히어로 일러스트와 장식용 빈 사진 영역은 두지 않는다.

### 상세: /[locale]/vets/[id] (제안)

병원명과 전화·지도 버튼을 먼저 배치한다. 이후 안내된 시간표, 야간·응급 진료의 조건, 영어 응대, 주소, 출처·확인일을 보여준다. 한국어 문의 문구는 상세 정보와 가까이 둔다.

모바일은 하단에 전화·지도 동작을 쉽게 찾도록 배치한다. 지도 임베드가 실패해도 전화번호·주소·외부 지도 링크가 남아 있어야 한다.

### 위치와 빈 상태

- 위치 허용: 위치 기준 가까운 순서. ‘직선거리’임을 명시하고 도착시간으로 바꾸지 않는다.
- 위치 미사용·거부: 구 선택으로 계속 탐색. 기본 목록을 사용자의 ‘내 주변’이라고 부르지 않는다.
- 위치가 없을 때 기본 정렬: 최근 정보 확인순. 거리순은 위치가 있어야 사용할 수 있다.
- 필터 결과 0건: 어떤 조건에 맞는 등록 정보가 없는지 표시하고 조건 해제를 제공한다.
- 서비스 지역 밖: 대전 시범 운영임을 알리고, 사용자가 선택해 현재 지역의 외부 지도 검색으로 이동할 수 있게 한다.
- 지도·외부 API 실패: 자체 병원 목록과 전화 기능 유지.

### 시간과 접수 상태의 구분

세 사실을 별도로 다룬다.

1. 안내된 진료시간: 병원이 공지하거나 직접 확인해 준 정규 시간.
2. 야간·응급 진료 운영: 해당 서비스를 제공한다는 안내와 적용 조건.
3. 현재 접수 가능 여부: 지금 해당 반려견을 받을 수 있다는 병원의 응답.

첫 출시에는 1·2를 제공한다. 현재 접수 상태를 알 수 없으면 ‘방문 전 전화 확인’으로 안내한다. 정규 시간표나 병원명에 포함된 ‘24시’만으로 ‘지금 응급 진료 가능’을 표시하지 않는다.

첫 출시는 시간표 표시를 우선한다. ‘현재 안내된 진료시간 내’ 필터는 자정 넘김, 휴게시간, 휴무일, 예외 일정, 정보 신선도를 처리할 수 있을 때 추가한다. 이 계산도 실시간 접수 확인과는 별개다.

## 5. 데이터 확보와 운영

### 권장 방식: 소규모 자체 확인 목록

시범 운영 목표는 병원 10~15곳 정도로 제안한다. 실제 확보 수나 대전 전체 병원 수를 뜻하지 않는다. 지역 분포와 확인 가능한 야간 진료·영어 응대 정보를 고려해 후보를 선정한다.

기본 정보는 병원 공식 홈페이지·공식 안내, 이용 조건을 확인한 공공 인허가 데이터 등을 후보 근거로 확보한다. 공공데이터의 실제 제공 필드, 갱신일, 이용 조건, 좌표 체계는 도입 전에 확인해야 하며 이번 조사에서 특정 데이터셋의 가용성을 확정하지 않았다.

후보 데이터는 관리자 검토를 거쳐 공개한다. 이름·주소·연락처·출처를 확인하고, 폐업 또는 이전 여부와 해당 지점 식별을 확인한다. 데이터 수집일과 병원 정보 확인일은 구분한다.

### 병원에 확인할 핵심 항목

- 대표 전화번호, 주소, 실제 안내할 지점
- 요일별 진료시간, 휴게시간, 접수 마감, 공휴일 안내
- 야간·응급 진료 운영 여부와 전화·예약 등 사전 조건
- 24시간 운영인 경우 실제 진료 범위와 시간 구분
- 영어 응대 여부, 가능한 요일·시간·방식
- 공식 홈페이지·안내 URL

병원 답변이 없으면 미확인으로 남긴다. 영어 응대와 야간 진료를 확인하지 못했다고 기본 연락처까지 모두 숨길 필요는 없으며, 확인된 정보의 범위가 보이도록 한다.

### 재확인

운영 초기에는 진료시간·야간 진료·영어 응대를 30일 주기로 재확인하는 안을 제안한다. 이는 서비스의 운영 가설이며 규정이나 보장 기준이 아니다. 실제 병원 수와 갱신 업무량에 따라 조정한다.

재확인 기한이 지나면 확인 이력을 유지하면서 ‘재확인 필요’를 표시한다. ‘안내 확인’ 필터에는 유효한 확인 근거가 있는 항목만 포함하고, 조건부인 경우 조건을 함께 노출한다. 오래된 정보나 부정 제보는 관리자 검토 대상으로 다루며 자동으로 사실을 확정하지 않는다.

일반 장소의 90일 기준을 동물병원에 그대로 적용하지 않고 별도 정책으로 관리한다.

### Google Maps·Places 활용 범위

첫 출시는 자체 병원 데이터와 외부 지도 링크를 중심으로 구현할 수 있다. Google Maps URLs는 검색·길찾기 링크에 API 키를 요구하지 않는다. 따라서 사이트의 지도 임베드 설정과 병원 연락 기능을 분리할 수 있다. 지역별 길찾기 지원과 기기별 링크 동작은 실제로 검증한다. [Google Maps URLs 공식 문서](https://developers.google.com/maps/documentation/urls/get-started)

Places API는 확장 단계에서 병원 후보 탐색·외부 정보 보완에 활용할 수 있다. 사용하려면 결제와 API 활성화가 필요하다. [Places API 개요](https://developers.google.com/maps/documentation/places/web-service/overview)

Places 응답을 자체 확인 데이터와 무분별하게 합쳐 영구 저장하는 구조로 설계하지 않는다. 저장·표시 정책을 확인하고, 자체 확인 정보의 출처와 외부 제공 정보를 구분한다. Place ID는 캐싱 제한의 예외로 장기 저장할 수 있다. [Places API 정책](https://developers.google.com/maps/documentation/places/web-service/policies)

Google의 영업시간 필드는 일정 정보를 제공하므로 병원의 현재 수용 가능 여부나 영어 응대 확인을 대신하지 않는다. [Places 응답 필드](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places)

## 6. 구현 구조 제안

병원은 기존 카페·여행지의 동반 조건 판정과 다른 도메인으로 다룬다. VET 카테고리만 추가해 병원이 목줄·이동장 필터와 반려견 입장 판정을 그대로 통과하게 만드는 구조는 피한다.

우선 별도 VetClinic 모델을 검토하되, 최종 물리 스키마는 현재 코드의 공통 장소 모델과 조회 구조를 확인해 결정한다. 브랜드 UI·인증·관리자 접근 제어·위치 처리·거리 계산·지도 링크·i18n 등 공통 기능을 재사용한다.

| 논리 데이터 | 최소 내용 |
|---|---|
| VetClinic | id, 원문명·공식 영문명(선택), 주소·구, 전화, 좌표, 공식 링크, 공개 상태 |
| 진료 안내 | 시간표·예외 안내·접수 마감 메모·시간대(Asia/Seoul), 정보 미확인 구분 |
| 응대·서비스 정보 | 영어 응대, 야간·응급 진료, 조건부 여부와 조건 설명 |
| ClinicVerification | 확인 항목, 확인 방식, 출처, 확인 시각, 수집 시각, 재확인 대상일 |
| 진료 준비 카드(P1) | 사용자가 선택한 반려견 정보, 사용자 원문, 번역문, 사용자 확인 상태 |

기존 Verification에 Place 외래키가 고정돼 있다면 무조건 재사용하지 않는다. 확인 기록의 공통 의미를 재사용하고, 병원 기록을 저장할 관계는 실제 스키마에 맞춰 설계한다.

영어 응대와 야간 진료는 서로 다른 확인 기록을 가질 수 있어야 한다. 특정 항목을 수정했다고 모든 정보의 확인일을 갱신하지 않는다.

진료 준비 카드는 첫 단계에서 자동 서버 저장·자동 병원 전송 없이 사용자 화면에서 생성·복사하도록 설계할 수 있다. 반려견 여러 마리 중 누구의 카드인지 명시하고, 비회원도 입력할 수 있게 한다.

필터·시간 해석·검증 신선도는 병원용 공통 함수에서 처리하고, 화면마다 판정을 복제하지 않는다. 기능 결정 ID는 기존 문서의 사용 현황을 확인한 뒤 부여한다.

## 7. AI를 붙이는 순서

### 1차: 고정 문장

검수한 한영 문장으로 문의를 돕는다. 모델 호출 없이 동작하며 전화 버튼은 항상 먼저 사용할 수 있다.

### 2차: 사용자 입력 기반 번역 카드

사용자가 관찰한 상황을 영어로 작성하면 다음 순서로 처리한다.

1. 사용자 원문과 이름·체중·시각 등 명시된 값을 받는다.
2. 전달용 한국어를 생성한다.
3. 원문·번역문을 함께 보여주고 사용자가 수정·확인하게 한다.
4. 확인한 내용을 복사하거나 화면으로 보여준다.

모델은 병명, 중증도, 투약량, 치료법, 원문에 없는 시간·수치·증상을 추가하지 않는다. 모르는 정보는 질문하거나 미확인으로 유지한다. 증상의 긴급도를 판정하는 기능은 이 번역 기능에 포함하지 않는다.

숫자·단위·부정 표현·시각·약 이름의 보존을 검증하고, 모델 검수만으로 번역 정확성이 보장된다고 판단하지 않는다. 자주 쓰는 표현은 사람 검수를 통해 고정 문장으로 축적한다.

호출 실패 시 원문과 고정 문의 문구를 계속 사용할 수 있게 한다. 이 기능의 모델·비용·보관 정책은 도입 시점에 별도로 선정한다.

### 3차: 병원 참여

제휴 병원이 직접 응대 조건을 갱신하거나 방문 문의에 응답하는 흐름을 검토한다. ‘현재 접수 가능’은 병원이 확인한 응답과 유효시간이 있을 때만 다룬다. 자동 문의 발송·예약 확정은 별도 기능과 사용자 동의를 갖춘 단계에서 구현한다.

## 8. 개발 순서와 단계별 산출물

| 단계 | 작업 | 끝났다고 판단할 근거 |
|---|---|---|
| 1. 작은 데이터 표본 | 후보 3~5곳의 공개 정보와 확인 가능한 항목을 정리 | 실제로 얻을 수 있는 값·미확인 항목·갱신 업무량 파악 |
| 2. 정책·데이터·관리자 | 필드·상태·공개 기준 확정, 입력·조회·확인 기록 구현 | 확인한 정보가 저장 후 동일하게 조회되고 수정 범위가 보존됨 |
| 3. 사용자 P0 | 목록·상세·검색·전화·지도 링크·ko/en·고정 문장 | 비회원이 위치 권한 없이도 병원을 찾아 전화할 수 있음 |
| 4. 시범 운영 | 목표 10~15곳 확보, 실제 모바일·사용자 확인 | 정보 출처와 상태가 정확하고 핵심 동선에 막힘이 없음 |
| 5. P1 확장 | 진료 준비 카드와 AI 번역 | 원문 보존·사용자 확인·실패 대체 경험 검증 |

고정 데이터 작업과 UI 개발은 병행할 수 있다. 실제 병원 답변을 기다리는 기간은 개발 작업량과 별도로 본다. 날짜별 일정은 기존 코드 재사용 범위와 운영에 쓸 수 있는 시간이 확인된 뒤 산정한다.

## 9. 출시 검증 기준

- 비회원이 병원 목록에서 바로 전화·외부 지도 열기를 할 수 있다.
- 위치 권한을 거부해도 구 선택·검색으로 탐색할 수 있다.
- 실제 병원명·지점·주소·전화번호와 연결 대상을 검증한다.
- 영어 응대 미확인, 조건부 영어 응대, 시간 미등록, 야간만 진료, 재확인 기한 경과를 구분한다.
- 야간 진료·영어 응대 필터가 자체 확인 기준에 맞게 동작한다.
- 결과 0건, 지도 실패, 데이터 조회 실패가 서로 다른 안내를 갖는다.
- ko/en에서 동일한 사실과 조건을 전달하고 이름·주소의 원문을 확인할 수 있다.
- 모바일에서 전화 버튼이 잘리지 않고 키보드 탐색·실제 확대를 확인한다.
- 시간 계산을 도입한다면 자정 넘김·휴게시간·임시 휴무·정보 미확인을 검증한다.
- P1 번역 카드는 원문에 없는 임상 정보를 추가하지 않고, 사용자 확인 후에만 전달하도록 한다.

개발 fixture는 실제 병원 정보처럼 공개하지 않는다. 운영 병원에 전화를 걸거나 문의 메시지를 보내는 것은 별도 운영 행위로 수행하며, 자동 테스트는 실제 발신 없이 링크·대상·동작을 검증한다.

## 10. 성공 지표

시범 운영에서는 다음 정도만 측정한다.

- 병원 페이지 진입 후 첫 전화 버튼 클릭까지 걸린 시간
- 병원 목록 조회 대비 전화·지도 버튼 클릭 비율
- 한국어 문의 문구 복사·확대 사용률
- 영어 응대·야간 진료 항목의 확인 정보 확보율
- 재확인 기한 경과율과 정보 오류 제보 건수

전화 클릭을 통화 연결·예약·실제 진료로 집계하지 않는다. 첫 사용성 확인은 소수의 한국 거주 외국인 보호자가 ‘병원 선택, 문의 문구 이해, 연락 시작’을 스스로 수행하는지 보는 방식으로 진행한다.

이 계획의 첫 목표는 병원 수를 크게 늘리는 것보다, 확인한 병원에 사용자가 실제로 연락할 수 있는 경험을 완성하는 것이다.
