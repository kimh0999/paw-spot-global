# 동물병원 탐색·문의 P0 — 구현·검증 분석

작성 2026-09-10 · 설계 `docs/02-design/동물병원-탐색-문의-P0.design.md`
· 계획서 `docs/04-report/Paw_Spot_Global_Vet_Clinic_Plan_v0.1.md`

## 1. 구현한 P0 범위

| 계획서 P0 | 구현 | 위치 |
|---|---|---|
| 병원 목록·상세 | ✅ | `/[locale]/vets`, `/[locale]/vets/[id]` |
| 이름·주소 검색, 구 선택 | ✅ | `filtering.ts` `filterVetClinics` · `VetsClient` |
| 위치 선택 시 가까운 순 | ✅ | 버튼 클릭 → `lat`/`lng`/`sort=distance` URL 반영 |
| 목록에서 전화·지도·주소 복사 | ✅ | `VetContactActions` (카드·상세 공용) |
| 안내된 진료시간 · 야간 조건 | ✅ | `operating-hours` 재사용 · `VetServiceBadge` |
| 영어 응대 4상태 | ✅ | `VetServiceStatus` |
| 항목별 출처·확인일·재확인 | ✅ | `VetVerification` · `resolveVetItem` · `VetVerificationLine` |
| 고정 한국어 문의 문구 (영어 뜻·복사·확대) | ✅ | `inquiry.ts` · `KoreanInquiryPhrases` |
| 관리자 등록·수정·임시저장·공개·숨김·확인 기록 | ✅ | `/[locale]/admin/vets/*` · `save-clinic.ts` |

**P1/P2는 구현하지 않았다** — 진료 준비 카드, AI 번역, 즐겨찾기·오류 제보, 예약·결제,
병원 직접 응답. 추측성 모델이나 빈 화면도 만들지 않았다.

## 2. 표시 규칙이 코드에서 지켜지는 지점

| 규칙 | 코드 |
|---|---|
| 시간 미등록 ≠ 휴무 | `hours === null` → `안내된 진료시간 없음` + 보조 설명 |
| 영어 응대 미확인 ≠ 불가 | `UNKNOWN` → 중립 아이콘·`미확인` |
| `24시`·영어 홈페이지로 추정하지 않음 | 상태는 관리자 입력값이며 이름·URL을 읽지 않는다 |
| `지금 접수 가능`을 계산하지 않음 | 시간표만 표시하고 `방문 전 전화 확인` 문구를 함께 낸다 |
| 좌표 없으면 거리 없음 | `distanceMeters`는 좌표+사용자 위치가 모두 있을 때만 |
| 거리순에서 좌표 없는 병원은 뒤로 | `sortVetClinics` |
| 위치 없을 때 `내 주변`이라 부르지 않음 | `최근 확인순` + 기준 문구 명시 |
| 재확인 30일, 일반 장소 90일 유지 | `VET_RECHECK_AFTER_DAYS=30` / `RECHECK_AFTER_DAYS=90` 분리 |
| 재확인 필요해도 숨기지 않음 | 목록에 남고 `재확인 필요`만 붙는다 |
| 조건부는 조건과 함께 | zod가 입력에서 강제 + `VetServiceBadge`가 함께 렌더 |
| 관리자 메모 비공개 | 공개 조회 `select`에서 제외 (테스트로 고정) |

## 4. 브라우저 검증 (격리 fixture)

마이그레이션 미적용이라 실데이터가 없다. **실제 페이지와 같은 컴포넌트**를 쓰는 임시
fixture 화면으로 확인한 뒤 삭제했다. (`VetClinicDetailView`를 라우트에서 분리한 이유다.)

| 확인 | 결과 |
|---|---|
| 목록 ko | 4곳, `최근 확인순 · 마지막으로 확인한 날 기준` 명시, 카드 순서 = 이름→구·주소→시간→응대→확인일→전화 |
| `영어 응대 안내 확인` 필터 | 4곳 → 1곳. 40일 경과·미확인·불가 모두 제외 |
| `야간 진료 안내 확인` 필터 | 4곳 → 1곳 |
| 결과 0건 | `병원 0곳` + 전용 문구 + `조건을 해제하고 전체 보기`. **필터 칩은 활성 그대로**(몰래 해제 없음) |
| 필터 상태 | URL 쿼리(`?english=confirmed&district=jung`) — 언어 전환에서 보존되는 근거 |
| 상세 ko | 전화/지도 먼저 → 시간표 → 조건 → 확인 근거 4항목 → 문의 문구 |
| 확대·닫기 | 다이얼로그에 한국어 4문장 + 영어 뜻 4개, `닫기`로 닫힘 |
| 전화·지도 링크 | `tel:0420000000`(비숫자 제거), `google.com/maps/search/?api=1&query=…` + `target=_blank rel="noopener noreferrer"`. **실제 발신 없이 대상만 확인** |
| 모바일 390×844 상세 | 가로 넘침 0, 고정 바 top=771·h=73, 마지막 문단 bottom=664 → **가리지 않음** |
| 목록 en | `4 clinics`, 영문명 우선·한국어명 보조, `No posted hours`·`English support · Unconfirmed`·`No location on file`·`Recheck needed` — ko와 같은 사실 |

## 5. 데이터 표본 — 확보하지 못했다

**출처 조회 결과 (2026-09-10)**

| 출처 | 확인한 것 |
|---|---|
| 국가동물보호정보시스템 동물병원 목록 (`animal.go.kr`) | 노출 필드가 **병원명·전화번호·소재지·인허가번호 4개뿐**이다. 진료시간·영어 응대·야간 진료 필드가 **없다.** 목록은 JavaScript 의존이라 정적 조회로 레코드를 뽑지 못했다 |
| 웹 검색 | 이 환경의 검색이 미국 기준이라 대전 병원 결과가 거의 잡히지 않았다. 후보 이름 몇 건만 보였고 주소·전화·시간을 확인할 수 없었다 |

**따라서 병원 3~5곳의 구체적 표본을 만들지 않았다.** 확인하지 못한 값을 채워 넣으면
그것이 곧 검증되지 않은 운영 데이터가 된다.

**그럼에도 필드 적합성은 확인됐다.** 공식 등록 시스템이 `BASIC`(이름·주소·전화)만 제공하고
`HOURS`·`ENGLISH_SUPPORT`·`AFTER_HOURS`는 제공하지 않는다는 사실이, **확인 근거를 항목별로
나눈 설계(D-17)가 필요한 이유를 그대로 뒷받침한다.** 등록 시스템에서 받은 기본 정보는
`WEBSITE` 방식의 확인 근거로 남기고, 나머지 세 항목은 병원 확인 전까지 `UNKNOWN`으로 둔다.
공개 기준을 기본 정보에만 건 것(D-20)도 같은 이유다 — 그러지 않으면 어떤 병원도 공개할 수 없다.

**공개 정보 조회를 전화 확인으로 기록하지 않는다.** 실제 병원에 전화·메시지를 하지 않았다.

## 6. DB 실검증의 한계

`.env.local`에는 **Supabase 운영 DB 하나뿐**이고 개발·테스트 DB가 없다.

- 마이그레이션 `prisma/migrations/20260910000000_vet_clinic/migration.sql`을 **작성·검토했고 적용하지 않았다.**
- 파괴적 변경이 없음을 확인했다: 기존 테이블·enum·데이터를 건드리지 않고 enum 2개·테이블
  2개·인덱스 3개·FK 1개만 추가한다. `PlaceVisibility`·`VerificationMethod`는 재사용한다.
- `prisma validate` 통과, `prisma generate`로 클라이언트 생성 확인.
- 따라서 **런타임 DB 조회는 검증하지 못했다.** 조회 실패 경로는 화면에서 다룬다 —
  목록은 `results.error` + 재시도, 관리자 목록은 마이그레이션 확인 안내를 낸다.

**적용 절차 (승인 후)**

1. 대상 DB 확인 → `npx prisma migrate deploy`
2. `\d "VetClinic"` / `\d "VetVerification"`로 컬럼·인덱스·FK 확인
3. `/ko/admin/vets`에서 등록 → 재조회 → 부분 수정 → 초기화 순서로 왕복 확인
4. `/ko/vets`에서 공개 병원만 보이는지, 임시저장·숨김이 URL 직접 접근으로도 안 열리는지 확인

## 7. 검증하지 못한 항목

| 항목 | 이유 |
|---|---|
| 실 DB 저장 후 재조회·부분 수정·초기화 | 마이그레이션 미적용 (§6). 로직은 단위 테스트로, 화면은 fixture로만 확인 |
| 관리자 권한 거부 경로 | `/admin/*` 레이아웃 가드와 액션의 `requireAdminAction`으로 구현했으나 실제 비관리자 세션으로 눌러 보지 못했다 |
| 실제 병원 데이터 | §5 |
| 실제 브라우저 200% 배율 | 기존 잔여 항목과 동일한 환경 제약 |
| Google Maps 결제·API 설정 | 기존 잔여 항목. **P0는 이 설정에 의존하지 않는다** — 지도 링크는 API 키가 필요 없다 |
