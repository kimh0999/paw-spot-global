## 4. 판단이 필요한 갭 (지연 범위 제외)

### G-1. `eligibility.ts` · `filtering.ts` 테스트 부재 — 회귀 위험 (P1)

설계 §"2단계 영향 요약"이 명시적으로 지목한 위험인데 아직 해소되지 않았다. 표시 계층을 건드리는 다음 단계에서 이 두 파일이 조건 해석의 단일 출처이므로, **착수 전에 최소 범위 테스트를 채우는 것을 권장**한다.

### G-2. `POOP_BAG` 정합성 규칙 부재 (P2)

`preparation.POOP_BAG`과 기존 `PlaceCondition.requiredItems`가 같은 사실을 가리키는데 둘을 맞춰 주는 규칙이 `condition-consistency.ts`에 없다. 현재는 관리자 체크박스에서 배변봉투를 제외해 **새 데이터에서 충돌이 생기지 않도록 회피**한 상태다. 규칙을 추가하거나, `requiredItems`를 `preparation`으로 흡수하는 설계 결정이 필요하다(설계 §C-3이 "조건부 · `preparation`으로 흡수 검토"로 남겨 둔 항목).

### G-3. 동시 수정 충돌 (P2, 구조적 한계)

서버 병합이 트랜잭션 안에 있으나 격리 수준이 READ COMMITTED라 동시 저장 시 마지막 쓰기가 이긴다. 낙관적 잠금이 없으면 완전히 막을 수 없으며, 이번 범위에서는 도입하지 않기로 했다.
