### F-1. 다견 매칭이 **미확인·불일치를 `조건 일치`로 단언**했다 (P1 · 수정 완료)

| 항목 | 내용 |
|---|---|
| 요구사항 근거 | 기획서 v3 §4-3(핵심 3조건 중 하나라도 미확인이면 확인 필요) · DESIGN.md §3.3 `Trust is explicit` · `matching.ts` 자체 헤더 주석 "확인되지 않은 조건을 허용으로 추정하지 않는다" |
| 관련 코드 | `src/lib/dogs/matching.ts` `matchDogToPlace` — 요약 컬럼 `place.indoor`만 읽고 `policyDetails`를 **아예 받지 않았다** |
| 기대 동작 | 동반 가능 여부가 확정되지 않으면 `CHECK_REQUIRED / UNKNOWN_CONDITION` |
| 실제 동작 | `MATCH`(`별이와 조건 일치`) |
| 영향 | 같은 장소를 두고 **상세·즐겨찾기는 `동반 조건 미확인`, 지도 목록만 `조건 일치`** |

**재현** — 아래 네 사례 모두 다른 화면과 어긋났다.

| # | 장소 조건 | 홈 카드 | 즐겨찾기(반려견 기준) | 지도 목록(수정 전) |
|---|---|---|---|---|
| C1 | `indoor=unknown`, 크기 확인됨 | `확인 필요` | `동반 조건 미확인` | **`조건 일치`** |
| C3 | `indoor=allowed` + 구역 기록 `실내·전체·불가` (불일치) | `확인 필요` | `동반 조건 정보 불일치` | **`조건 일치`** |
| C4 | `indoor=unknown` + 구역 기록 `실내·전체·불가` | `확인 필요` | `동반 조건 미확인` | **`조건 일치`** |
| C4' | `indoor=not_allowed` + 구역 기록 `실내·전체·허용` | `확인 필요` | `동반 조건 정보 불일치` | **`동반 불가` 단언** |

C4가 가장 나쁘다. **구역 기록이 "실내 전체 불가"라고 말하는데 목록은 `조건 일치`라고 했다.**

**원인.** `matchDogToPlace`가 `resolveDogAccess`를 쓰지 않고 `place.indoor === "not_allowed"`만
봤다. 그래서 (a) `policyDetails.spaceExceptions`를 전혀 읽지 않았고 (b) `unknown`을 "불가는
아니다 → 일치"로 처리했다. 테스트 `"실내 조건이 미확인이어도 동반 불가로 보지 않는다"`가
의도(불가로 보지 말 것)는 맞았지만 단언을 `MATCH`로 적어 **결함을 고정하고 있었다.**

**수정.** `MatchablePlace`에 `policyDetails`를 **필수 필드**로 넣고 판정을 `resolveDogAccess`로
옮겼다. 동반 가능이 확정된 상태(`allowed`·`outdoorOnly`·`partialArea`)에서만 `MATCH`를 낸다.
필수로 둔 덕분에 같은 누락이 있던 **상세 화면 호출부**(`places/[id]/page.tsx`)가 컴파일 오류로
드러나 함께 고쳤다.

- D-05(`현행 3상태 유지`)를 지킨다 — 상태를 추가하지 않고 기존 `CHECK_REQUIRED`를 쓴다.
- 준비 항목(`preparation`)은 여전히 판정 밖이다. 판정 근거는 크기·견종·**동반 가능 여부**뿐이다.
- 회귀 테스트 4건. 수정 전 4건 실패 → 수정 후 통과.

## 4. 의도된 변경 (결함 아님)

### I-1. 홈은 `조건부 방문 가능`, 즐겨찾기는 `방문 가능 · 별이 기준`

**두 판정은 서로 다른 질문에 답한다.** 통일하면 안 된다.

| | 함수 | 묻는 것 | 보는 조건 |
|---|---|---|---|
| 홈 카드 | `getVisitStatus(place, "all")` | 이 장소에 **지켜야 할 조건이 있는가** | 동반 여부·이동장·크기 상한·목줄·입마개 전부 |
| 즐겨찾기 | `getVisitEligibility(place, dogSize)` | **우리 별이가 입장할 수 있는가** | 입장을 가르는 조건 + 크기 대조 |

몽베르트(`실내 가능` / `이동장 불필요` / `중형견까지` / `목줄 필수` / `입마개 조건부`)는
목줄·입마개 때문에 `조건부`이고, 소형견 별이 기준으로는 입장 조건을 통과하므로 `방문 가능`이다.
**둘 다 사실이다.**

**방문 준비 조건은 누락되지 않는다** — 실제 화면에서 확인했다.

- 즐겨찾기 카드: 판정 아래 전체 5조건(`목줄 필수`·`상황에 따라 입마개 필요` 포함)
- 미리보기: 두 판정을 **나란히** 띄우고 `가능해요` / `조건이 있어요`로 나눠 전체 조건 표시
- DESIGN.md §6 Place Card가 요구하는 "입장 조건만 본 판정 아래에는 나머지 조건이 함께" 충족

### I-2. 지도 목록은 이동장 미확인이어도 `조건 일치`

목록 배지(`dogMatch`)의 근거는 DESIGN.md §6 Visit Verdict가 **크기·견종·동반 가능 여부**로
못박았고, 문구도 `조건 일치`(프로필 대조)이지 `방문 가능`이 아니다. 이동장 조건은 같은 카드의
핵심 3조건 목록에 `이동장·유모차 필요 여부 미확인`으로 그대로 보인다. 범위를 넓히지 않았다.

## 6. F-2. 지원하지 않는 locale이 홈을 렌더했다 (P1 · 수정 완료)

**증상.** dev 로그에 `IntlError: INVALID_MESSAGE: Incorrect locale information provided (undefined)`가
페이지 로드마다 9건.

**확인 방법과 결과.**

1. `curl http://localhost:3101/ko` → 오류 **0건**. 브라우저로 같은 URL → **9건**. (curl은 favicon을 요청하지 않는다)
2. `[locale]/layout.tsx`에 `locale` 값을 임시로 로그 → `GET /favicon.ico` 요청에서
   **`[PROBE] layout locale = "favicon.ico"`**. 정상 요청은 `"ko"`.
3. 1회차 로그에서도 IntlError 블록 바로 뒤가 `GET /favicon.ico 200`이다.
4. 저장소에 `public/favicon.ico`도 `src/app/favicon.ico`도 **없다**.

**원인.** 미들웨어 matcher `/((?!api|_next|_vercel|.*\..*).*)`는 점이 든 경로를 제외하지만,
그건 미들웨어일 뿐이고 **라우트 `[locale]`은 여전히 `/favicon.ico`에 매칭된다.** 실제 파일이
없으니 `locale = "favicon.ico"`로 전체 트리가 렌더되고, `NextIntlClientProvider`에 잘못된
로케일이 들어가 `Intl` 포맷이 실패한다. `getMessages()`는 `hasLocale` 검사로 기본 로케일
메시지를 돌려주므로 **메시지는 정상이고 로케일만 깨진다** — 그래서 자리표시자가 있는 메시지만
실패했다.

**수정 (2026-09-10).** 로그만 끄는 조치는 쓰지 않았다 — 그러면 favicon 요청마다 홈이
렌더되고 DB를 조회하는 문제가 그대로 남는다. 두 겹으로 막았다.

1. **`src/app/favicon.ico`** — 브랜드 마크(`PawSpotMark`)의 도형·색을 그대로 옮겨 16·32·48px
   ICO로 생성했다(`scripts/generate-favicon.mjs`). 이제 `/favicon.ico`는 Next의 파일 규약이
   처리하므로 `[locale]`에 닿지 않는다. `metadata.icons`를 따로 두지 않아 같은 URL을 두 번
   정의하지 않는다.
2. **`assertSupportedLocale`** (`src/i18n/assert-locale.ts`) — `[locale]/layout.tsx`에서
   호출한다. `/nope.ico`처럼 favicon이 아닌 점 있는 경로도 404로 끊는다. 프로덕션 빌드에서는
   `dynamicParams = false`가 한 겹 앞에서 같은 요청을 막지만 **dev 서버에는 적용되지 않아**
   (dev는 모든 라우트를 동적으로 렌더) 두 환경을 같게 만드는 것은 이 함수다.

**레이아웃 가드가 페이지 조회까지 막는지 추정하지 않고 측정했다.** 요청별 `prisma:query` 수를
세었다.

| 요청 | 수정 전 | 수정 후 |
|---|---|---|
| `/favicon.ico` | 200 `text/html` · prisma 4 · IntlError 18 | **200 `image/x-icon` · prisma 0 · IntlError 0** |
| `/nope.ico` | 200 `text/html` · prisma 4 · IntlError 18 | **404 · prisma 0 · IntlError 0** |
| `/apple-touch-icon.png` | 200 `text/html` · prisma 4 | **404 · prisma 0** |
